# Reviewing Pull Requests

*Last updated: 16 August 2026*

Alongside **[managing applications](./managing-applications.md)**, the
Maintainer view gives you a live feed of every pull request across your
connected projects — useful for keeping tabs on what's actually landing,
not just who's applied.

## Where to look

Open **Maintainers → Pull Requests**. You'll see every pull request across
your connected projects in one list, each showing its title, author, target
repository, and current state.

Filter by state — **All**, **Open**, **Merged**, or **Closed** — and use
search to jump straight to a specific pull request by title. Each entry
links straight through to the pull request on GitHub.

:::tip
This is a read view into what's happening on GitHub, not a separate review
tool — approving, requesting changes, and merging still happen on GitHub
itself. Grainlify's Pull Requests tab is for keeping an eye on volume and
status across every project you maintain without switching between repos.
:::

## Why it's useful

If you maintain more than one project on Grainlify, this is the fastest way
to answer "what's in flight right now?" across all of them at once, instead
of checking each repository's own pull request tab individually — especially
handy right after an **[Open Source Week](./ecosystems-and-events.md)** push,
when merge activity picks up across the board.
