# Getting Started as a Maintainer

*Last updated: 16 August 2026*

Listing your project on Grainlify puts it in front of contributors actively
looking for issues to work on, and gives you a dashboard for reviewing who
wants to help.

## Switch to Maintainer view

Sign in with GitHub like any contributor, then use the **Contributor /
Maintainer** switcher in the top navigation and select **Maintainer**. This
swaps in the tools for managing your own projects — your contributor account
and your maintainer tools are the same account, just a different view.

:::note What the switch actually does
Flipping to Maintainer view just changes which tools are shown — it doesn't
grant any new capability by itself. What you can actually *do* as a
maintainer (assign or reject applications, see a project's applicants) is
scoped entirely by which repositories you've installed the Grainlify GitHub
App on, covered next. Switching views on an account with no connected
repositories just shows you an empty maintainer dashboard.
:::

## Connect your project

1. From the Maintainer view, choose **Add a repository**.
2. You'll be sent to GitHub to install the Grainlify GitHub App on your
   account or organization, and pick which repositories to share with it.
   GitHub itself is what gates this step — only someone with admin rights on
   the org or repo can complete the install.
3. You'll land back on Grainlify with your public repositories connected.
   (Private repositories are never listed or synced — only public ones.)

## Finish setup to go live

A newly-connected project isn't visible to contributors yet. Fill in its
setup details:

- **Description**
- **Ecosystem** — pick from the communities already on Grainlify (see
  **[Ecosystems & Events](./ecosystems-and-events.md)** if you don't see the
  right one)
- **Primary language**
- **Category** — Frontend, Backend, Full Stack, DevOps, or Mobile
- **Tags**

As soon as you save this, your project appears on **Discover** and
**Browse** for every contributor on the platform.
